## 1. 제품 한 줄과 전제

**느린 길(Slow Way)**은 직장인이 업무 경험을 틈틈이 기록하고, 기록을 AI로 구조화해 경험 단위로 쌓고, 필요할 때 커리어 컨텍스트 파일로 내보내 본인의 생성형 AI에서 경력기술서·자기소개서·면접 자료를 만들게 하는 **로컬 실행 웹 도구**다.

01 컨셉 문서(iOS 앱, 앱 내 AI 호출, PDF 출력)와 달라진 전제는 결정 로그에 있다. 이 문서는 그 결정 위에서 쓴다.

| 전제 | 결정 | 이 문서에 미치는 영향 |
|------|------|----------------------|
| 플랫폼: 사용자 PC에서 `run.bat`으로 실행하는 로컬 웹 (FastAPI + React) | D-006 | 호스팅·로그인·동기화·푸시 알림 없음. 데스크톱 1093px 기준 |
| 앱은 AI API를 호출하지 않는다. 구조화는 프롬프트 왕복, 활용은 컨텍스트 파일 내보내기 | D-001, D-008 | "AI 기능"은 전부 "프롬프트 생성 + 응답 파싱"으로 정의된다 |
| 무료 전용, 외부 요청 0 | D-005, D-008 | 비용·할당량·결제 요구사항 없음 |
| 데이터는 개인 PC의 vault 폴더 (Markdown + SQLite 파생 색인) | D-006, D-009 | 백업·전체 내보내기가 MVP에 들어간다 |
| 1차 페르소나: 제조·AX/DX 대기업 10년차 이상 팀장급, 이직과 사내 평가 두 상황 | D-004 | 콜드 스타트(기존 경력기술서 분해)가 M0 |
| 경험 모델: 교훈·구분·확인 필요 필드, 정량 성과 네 칸 | D-010 | 4절 FR-C·FR-E |
| 구조화 응답은 `slow-way` 블록의 `키: 값` 줄 형식, 관용 파서 | D-011 | FR-C, NFR-10 |

## 2. 용어

`04_DATA_MODEL.md` 1절을 따른다. 경력(Career) → 과제(Project, 선택) → 경험(Experience) ← 기록(Entry). 역량(Skill), 증빙(Evidence), 정량 성과(Quant). STAR는 상황·목표·행동·결과. 화면·프롬프트·문서는 이 한국어 이름만 쓴다.

## 3. 사용자와 시나리오

### 3.1 사용자

- **1차**: 제조·AX/DX 분야 대기업 10년차 이상 팀장급. 경력기술서가 이미 있고(5장 안팎), 이직 준비와 사내 평가·승진 자료를 번갈아 쓴다. 사내 PC는 인터넷이 차단되어 있고 개인 PC는 자유롭다. 본인 AI 계정(ChatGPT·Gemini·Claude 중 하나 이상)이 있다.
- **2차(베타 후)**: 3~7년차 실무자. 경력기술서가 없거나 짧다.
- 개발자 본인이 1차 페르소나이며, 실험 01의 데이터가 그 경력이다.

### 3.2 시나리오 (요구사항 번호는 4절)

**S1. 첫 사용: 기존 경력기술서로 시작 (30분)**
앱을 설치하고 켠다 → 프로필과 경력(회사·조직·직위·기간)을 입력한다 → 경력기술서 텍스트를 붙여 넣어 기록으로 저장한다 → 앱이 분해 프롬프트를 만들어 준다 → 본인 AI에 붙여 넣고 응답을 받아 앱에 붙여 넣는다 → 경험 20여 건이 "구조화" 상태로 생긴다 → 하나씩 열어 "확인 필요"에 답하고 확정한다 → 컨텍스트 파일을 내보내 본인 AI에 넣고 경력기술서 초안을 받아 본다. (FR-A, FR-B, FR-D, FR-C, FR-E, FR-H)

**S2. 평상시: 한 줄 기록 (2분)**
오늘 한 일을 한두 문장 적고 저장한다. 끝. 구조화는 하지 않아도 된다. (FR-B)

**S3. 주말 정리: 기록을 경험으로 (10분)**
구조화되지 않은 기록이 쌓이면 앱이 묶어서 구조화 프롬프트를 만든다 → AI 응답을 붙여 넣는다 → 새 경험이거나 기존 경험의 이어짐으로 들어간다 → 질문에 답하고 확정한다. (FR-C, FR-E, FR-F)

**S4. 이직 준비: 내보내기 (5분)**
범위(전체/경력별/선택)와 익명화 여부를 고르고 목적(경력기술서/자기소개서/면접)을 고른다 → 컨텍스트 파일과 프롬프트를 받는다 → 본인 AI에서 문서를 만든다 → 결과물의 근거 ID를 지우고 제출한다. (FR-H)

**S5. 평가 시즌: 올해 성과 (5분)**
기간을 올해로 잡아 내보내고, 평가·승진 자료용 프롬프트를 쓴다. (FR-H, M1 프롬프트)

**S6. 퇴사·전배: 데이터 이동**
전체 내보내기(zip)로 vault를 개인 PC로 옮긴다. 사내 PC에는 남기지 않는다. (FR-I)

### FR-C. 구조화 왕복 (프롬프트 생성 → 응답 파싱 → 검토 → 확정)

| # | 요구사항 | 우선 |
|---|----------|------|
| FR-C1 | 선택한 기록 1건 또는 여러 건으로 **구조화 프롬프트**를 만든다. 내용은 `docs/prompts/structure_entry.md`를 따르고, 앱 설정의 접두·접미 문구, 역량 사전, 최근 경험 목록(ID·제목·기간 20건)을 채워 넣는다 | M0 |
| FR-C2 | 프롬프트는 **복사 전에 전문을 화면에 보여 준다**. 무엇이 나가는지 보지 않고 복사할 수 없다 (느린 나이테 `AiPromptPanel` 원칙) | M0 |
| FR-C3 | 프롬프트 화면에 "이 글은 당신이 고른 AI 서비스로 갑니다. 그 서비스의 데이터 정책을 확인하세요"와 민감정보(영업비밀·고객명) 주의 문구를 고정 표시한다 | M0 |
| FR-C4 | 사용자가 AI 응답을 붙여 넣으면 **파서**가 `slow-way` 블록을 찾아 경험 필드에 채운다. 파서는 `docs/spec/context_file.md` 3.3의 규칙 15개를 따른다: 펜스 없이 "형식:" 줄로 블록 인식, Gemini 인용 표식 제거, 스칼라 키 아래 목록 허용, 기준 칸 접두어 제거, 빈 값 정규화, 정량 성과 칸 수 처리 | M0 |
| FR-C5 | 파싱 결과를 **저장 전에 미리보기**로 보여 준다 (미리보기 GET / 실행 POST 쌍). 블록별로 "새 경험으로 / 기존 경험 E-nnn에 이어서 / 버림"을 고른다. AI가 적은 `이어짐: E-nnn`은 기본값일 뿐 사용자가 바꾼다 | M0 |
| FR-C6 | 읽지 못한 줄은 줄 번호와 원문을 보여 주고, 읽은 부분만 채운다. 블록이 하나도 없으면 "형식 블록이 없습니다" 안내와 함께 원문을 기록으로만 저장한다 | M0 |
| FR-C7 | 기존 경험에 이어 붙일 때 **사용자가 수정한 필드는 덮어쓰지 않는다**. AI 값은 옆에 나란히 보여 주고 사용자가 고른다 (검토 문서 B1, 느린 나이테 TODO 113 원칙) | M0 |
| FR-C8 | 경험의 "확인 필요"는 질문 목록이다. 각 질문에 답을 쓰면 해당 필드에 반영되고 질문은 지워진다. "해당 없음"도 답이다 | M0 |
| FR-C9 | 역량 이름은 역량 사전의 동의어로 대표 이름에 매핑한다. 매핑 안 되면 "새 역량" 후보로 표시해 사전에 추가하거나 기존 이름으로 바꾸게 한다 (04 §9) | M0 |
| FR-C10 | 구조화 응답에서 역할 필드가 비어 있거나 주체 구분이 없으면 확정 전에 "본인이 한 일 / 다른 주체가 한 일"을 묻는다 (R-07) | M0 |
| FR-C11 | 같은 응답 안의 수치·제목이 겹치는 블록을 **중복 후보**로 표시한다 (R-02, X-08) | M0 |

## 8. AI 품질 기준 (06_AI_DESIGN의 입력)

앱은 AI를 호출하지 않으므로 "품질"은 ① 프롬프트가 좋은 응답을 끌어내는가 ② 파서가 응답을 읽는가 ③ 결과물이 사실을 지키는가로 정의한다. 실험 01의 채점표(0~2점, 사실·수치·형식·제출)를 그대로 쓴다.

| 기준 | 목표 | 측정 |
|------|------|------|
| 활용 프롬프트 수치 보존 | 3개 서비스 모두 2점 | 실험 01에서 달성. 프롬프트를 바꿀 때마다 A 1회씩 재검 |
| 활용 프롬프트 사실 정확성 | 서비스 평균 1.5 이상 | 실험 01: ChatGPT 1.7, Gemini 1.0, Claude 2.0 |
| 분해 응답 파싱률 | 블록 단위 100% (읽지 못한 줄은 보여 주되 블록은 살림) | 실험 01 응답 3종을 고정 시험 자료로 |
| 분해 대응률 | 수작업 분해 대비 70% 이상의 경험이 블록으로 생김 | Claude 100%, ChatGPT 74%, Gemini 약 60% |
| 구조화(기록 1건) | 골든 세트 20~30개로 회귀 검증 | 미실험. 06에서 골든 세트 작성 |
| 질문 품질 | 열린 질문, "없음"이 정상 답. 3개 이내 | 프롬프트 규칙 |

## 9. 성공 지표

로컬 도구이므로 서버 수집은 없다. 앱이 vault 안에 **로컬 카운터**를 두고 설정에서 사용자가 보며, 베타 때는 사용자가 수치를 알려 준다.

| 지표 | 목표 | 산출 |
|------|------|------|
| 기록 1건 소요 시간 중앙값 | 2분 이내 | 기록 화면 진입 → 저장 |
| 첫 사용 30분 안에 컨텍스트 파일 내보내기 도달 | 베타 테스터 70% | 설치 시각 → 첫 내보내기 시각 |
| 4주 후 주간 기록 사용자 비율 | 50% | 주별 기록 유무 |
| 구조화 경험 중 확정 비율 | 60% | 상태 카운트 |
| 내보내기 실행 사용자 비율과 재실행률 | 베타 80%, 2회 이상 50% | 내보내기 이력 |
| 내보내기 후 "실제 문서 작성에 썼는가" | 베타 설문 | 설문 |
| 파싱 실패율 (블록 없음 / 전체 붙여넣기) | 5% 이하 | 파서 카운터 |

## 1. 무엇을 내보내는가

| 산출물 | 용도 | 형식 | 우선 |
|--------|------|------|------|
| 커리어 컨텍스트 파일 | 사용자 AI에 첨부해 문서를 만든다 | `.md`, 스펙 2절 | M0 |
| 활용 프롬프트 | 파일과 함께 붙여 넣는다 | 텍스트, use_context_file.md A·B·C | M0 |
| 파일 + 프롬프트 합본 | 첨부가 안 되는 경로(본문 붙여넣기)용 | 텍스트 | M0 |
| 결과물 정리 | AI가 만든 문서에서 근거 ID를 지우고 익명화를 되돌린다 | 텍스트 (저장 안 함) | M0 |
| 전체 백업 | 이동·보관 | `.zip` (vault 전체) | M0, FR-I |
| JSON | 기계 가독 이관 | `.json` | M1 |

PDF와 앱 내 문서 생성은 만들지 않는다(D-001, 실험 01로 재확인).

## 2. 흐름

```text
[1 범위]  전체 / 경력 고르기 / 기간 / 경험 직접 고르기
           + 상태: 확정만(기본) / 구조화 포함
              │
[2 옵션]  익명화 켜기·끄기 (치환표 확인)
           근거 ID 넣기(기본 켬)
              │
[3 목적]  경력기술서 / 자기소개서 / 면접 질문  (M1: 평가 자료, 이력서 요약)
           채용공고(JD) 붙여넣기 (선택)
              │
[4 미리보기] 요약 카드 + 경고 + 파일 전문 + 프롬프트 전문
              │
[5 내보내기] 파일 저장(.md) · 파일 내용 복사 · 프롬프트 복사 · 합본 복사
```

- 1~3은 한 화면의 왼쪽 패널, 4·5는 오른쪽 패널이다(03_UX_SPEC S-08). 옵션을 바꾸면 미리보기가 즉시 다시 그려진다.
- 미리보기는 서버 GET(만들기만)이고, 저장·복사는 브라우저가 미리보기 결과를 그대로 쓴다. **미리보기에 표시된 문자열이 곧 출력**이다. 미리보기와 다른 내용이 나가는 일은 없다.
- 5에서 무엇을 하든 vault에는 아무것도 쓰지 않는다. M1의 내보내기 이력(FR-H10)만 범위·옵션·시각을 남긴다.

## 3. 범위 선택 규칙

| 범위 | 포함 경험 | 포함 경력·과제 |
|------|-----------|----------------|
| 전체 | 상태 조건을 만족하는 전부 | 경력은 전부(이력의 빈칸 방지). 과제는 포함 경험이 있는 것만 |
| 경력 | 고른 경력이 **주 경력**인 경험 + `related_careers`에 고른 경력이 있는 경험 | 고른 경력 |
| 기간 | 경험 기간이 범위와 **겹치는** 경험. 기간이 빈 경험은 제외하고 경고 | 포함 경험의 경력 |
| 직접 선택 | 체크한 경험 | 포함 경험의 경력 |

- **상태 조건**: 기본은 `확정`만. "구조화 포함"을 켜면 `구조화`도 넣고 미리보기 경고에 "확정되지 않은 경험 n건이 들어갑니다"를 띄운다. `초안`은 어떤 옵션으로도 넣지 않는다.
- **관련 경험 끌어오기 없음**: 포함 경험이 범위 밖 경험을 `related`로 가리켜도 끌어오지 않는다. 파일에는 ID만 남고 경고에 "범위 밖 경험 E-nnn을 참조합니다"를 띄운다.
- 포함 경험이 0건이면 내보내기 버튼을 끄고 이유를 보여 준다.

## 4. 직렬화 규칙 (vault → 파일)

스펙 2절의 순서를 따른다. 여기서는 스펙이 정하지 않은 세부를 정한다.

### 4.1 front matter

```yaml
format: slow-way-career-context
version: 0.2
exported_at: 2026-11-07
owner: 홍길동             # 익명화면 "익명"
scope: 전체               # "경력 C-04", "기간 2023-01~2024-12", "선택 12건"
status_included: 확정     # 또는 "확정+구조화"
anonymized: false
experience_count: 21
app: slow-way 0.1.0       # 배포본 이름
```

### 4.2 본문 순서와 필드

| 절 | 원천 | 규칙 |
|----|------|------|
| 사용 안내 (AI에게) | 설정의 사용 안내문 (기본값 = 스펙 2.2) | 사용자가 고쳐 쓸 수 있다. 비우면 기본값 |
| 프로필 | `profile.md` + 경력 표에서 계산한 총 경력 + 모든 경험의 증빙 중 특허·수상 | 특허·수상은 프로필에 한 번 모아 보이고, 각 경험의 증빙에도 남긴다 |
| 경력 | `careers/` | 역순. 표 한 장 |
| 과제 | `projects/` | 포함 경험이 있는 과제만. 0개면 절 생략 |
| 경험 | `experiences/` | 시간 **역순**(최근 먼저). 스펙 2.3 블록 |
| 역량 색인 | 경험의 `skills` 집계 | 축별, 관련 경험 수 내림차순 |
| 정량 성과 목록 | 경험의 `quants` 집계 | 경험 역순. `baseline_kind`가 `비교`면 기준 칸에 기준, 아니면 "기준 없음" |

**경험 블록의 빈 필드**: 값이 없는 줄은 **생략한다**. 단 `역할`, `구분`, `상태`는 항상 쓴다. 실험 01에서 빈 줄은 AI가 채워 넣으려 하거나 미확정으로 오해했다.

**확인 필요**: `확정` 경험은 확인 필요가 비어 있으므로(04 §4 조건 3) 절이 생기지 않는다. `구조화` 포함 시에만 나타나고, 사용 안내문의 "확인 필요 단정 금지" 규칙이 이를 다룬다.

**기간 표기**: `YYYY-MM ~ YYYY-MM`, 진행 중은 `YYYY-MM ~ 현재`, 월이 없으면 `YYYY`. 빈 값은 줄 생략.

**정렬 안정성**: 같은 시작 월이면 ID 오름차순. 같은 vault에서 같은 옵션으로 내보내면 `exported_at` 외에는 **바이트 단위로 같은 파일**이 나와야 한다(8절 시험).

### 4.3 근거 ID

- 기본은 넣는다. 경험 제목 `## [E-001] …`와 역량 색인·정량 성과 목록의 ID 칸.
- "근거 ID 빼기"를 고르면 제목에서 `[E-nnn]`을 빼고 색인·목록의 ID 칸을 경험 제목으로 바꾼다. 사용 안내문의 "근거 ID를 괄호로 남긴다" 문장도 뺀다. 실험 01에서 ID가 채점·검증 시간을 크게 줄였으므로 기본값은 켬이다.

### 4.4 크기

| 기준 | 동작 |
|------|------|
| 10만 자 이하 | 그대로 |
| 10만 자 초과 | 경고: "파일이 큽니다(n자). 본문 붙여넣기 경로에서는 잘릴 수 있습니다. 범위를 줄이거나 첨부로 쓰세요" |
| 30만 자 초과 | 경고 + 경력별로 나눠 내보내라는 안내. 자동 분할은 하지 않는다(M2 검토) |

실험 01의 경험 25건이 약 22,000자였으므로 100건이면 약 9만 자다.

### 4.5 파일 이름

`slow-way-career-context_{소유자}_{범위}_{YYYYMMDD}.md`

- 소유자는 익명화면 `익명`. 범위는 `전체`, `C-04`, `2023-2024`, `선택12`.
- 윈도우 금지 문자 제거, 공백은 `-`. 느린 나이테 `vault/paths.py`의 안전 파일명 함수를 쓴다.

## 5. 익명화

재직 중 이직 준비에서 회사명·인명이 외부 AI로 나가는 것을 막는다. 앱이 하는 일은 **사용자가 정한 치환표를 정확히 적용하고, 빠진 것을 찾아 경고하는 것**이다. 고유명사를 자동으로 다 찾아낼 수는 없다.

### 5.1 치환표

`vault/anonymize.yaml`에 둔다. 04 §11의 미결 "치환표 저장 위치"를 여기서 정한다: **vault 안**. 치환표의 실명은 vault의 경험 파일에 이미 있고, vault를 옮길 때 치환표도 함께 가야 같은 자리표시자가 유지되기 때문이다.

```yaml
schema: 1
rules:
  - {kind: 회사, from: 가나철강, to: A사}
  - {kind: 회사, from: Gana Steel, to: A사}
  - {kind: 조직, from: 품질AI팀, to: A팀}
  - {kind: 조직, from: 스마트공장팀, to: B팀}
  - {kind: 인명, from: 홍길동, to: 본인}
  - {kind: 공정, from: 압연 표면 결함, to: 표면 결함}
  - {kind: 기관, from: 다라대학교, to: C대학}
patterns:
  - {kind: 특허번호, regex: '10-\d{7}', to: '특허 등록번호'}
```

- `kind`: 회사 / 조직 / 인명 / 제품 / 공정 / 고객 / 기관 / 기타. 미리보기 요약에 종류별 치환 횟수를 보인다.
- 같은 `to`를 여러 `from`이 써도 된다(국문·영문 회사명).
- `patterns`는 정규식. 기본으로 국내 특허 등록번호(`10-\d{7}`) 하나를 넣어 둔다.

### 5.2 후보 자동 추출

익명화를 처음 켜면 치환표가 비어 있을 수 있다. 앱이 후보를 뽑아 체크 목록으로 보여 주고, 사용자가 고르고 `to`를 정한다.

| 출처 | 후보 |
|------|------|
| 경력 | `company` 전부, `org` 전부 |
| 프로필 | 이름, 학교 |
| 증빙 | 수상명 안의 회사명, 특허 제목 |
| 본문 | 영문 대문자로 시작하는 2단어 이상 고유명사, "○○사"·"○○팀"·"○○본부" 꼴 |

후보는 제안일 뿐이다. 인명·고객명은 거의 못 찾으므로 미리보기 안내에 "사람 이름과 고객사 이름은 직접 넣으세요"를 고정한다.

### 5.3 적용 순서

1. 직렬화가 끝난 **최종 문자열**에 적용한다(필드별 적용 아님). front matter의 `owner`는 `익명`이 된다.
2. `rules`를 `from`의 **길이 내림차순**으로 적용한다. "가나철강"이 "가나"보다 먼저 바뀌어야 한다.
3. 한국어 조사가 붙어도 바뀌도록 **부분 문자열 치환**을 쓴다("가나철강의" → "A사의"). 영문 `from`은 단어 경계를 지킨다.
4. `patterns`를 적용한다.
5. 근거 ID `E-nnn`, `C-nn`, `P-nn`은 치환 대상에서 보호한다.

### 5.4 잔존 검사

치환 뒤 문자열에서 모든 `from`을 다시 찾는다. 하나라도 있으면(대소문자·전각 차이 등) 경고하고 위치를 보여 준다. 5.2 후보 중 치환표에 없는 것이 결과에 남아 있으면 "치환되지 않은 후보 n개"를 경고한다. 경고가 있어도 내보내기는 막지 않는다. 판단은 사용자 몫이다.

### 5.5 되돌리기

자리표시자는 결과물 정리 도구(7절)에서 실명으로 되돌릴 수 있다. 같은 `to`를 여러 `from`이 쓰면 **치환표에서 먼저 적은 규칙**의 `from`으로 되돌린다(국문 회사명을 먼저 적게 안내).

## 6. 미리보기

FR-H6. 사용자가 앱 안에서 "완성된 것"을 보는 유일한 순간이다(00 §0 위험). 오른쪽 패널 위에서부터:

1. **요약 카드**
   - 경험 n건 (확정 a / 구조화 b), 기간 YYYY-MM ~ YYYY-MM, 경력 n개
   - 역량 축별 막대 4개(관련 경험 수), 상위 역량 5개
   - 정량 성과 n개 (비교 a / 기준 없음 b)
   - 파일 크기 n자, 익명화 치환 n회(종류별)
2. **경고 목록** (있을 때만, ⚠ + 문장)
   - 확정되지 않은 경험 포함 / 범위 밖 참조 / 기간 없는 경험 제외 / 크기 / 익명화 잔존·미치환 후보 / 정합성 경고가 남은 경험 포함
3. **탭: 파일 / 프롬프트 / 합본**
   - 파일: 렌더링 보기와 원문 보기 전환. 원문 보기가 실제로 나가는 글이다
   - 프롬프트: 고른 목적의 프롬프트 전문. JD를 넣었으면 채워진 상태
   - 합본: 프롬프트 + 구분선 + 파일
4. **버튼**: 파일 저장 / 파일 복사 / 프롬프트 복사 / 합본 복사
5. **고정 문구**: "이 파일은 당신이 고른 외부 AI 서비스로 전달됩니다. 익명화 옵션을 확인하세요." (FR-H8)

## 7. 결과물 정리 도구

FR-H9를 넓힌다: 근거 ID 지우기에 익명화 되돌리기와 메모 절 지우기를 더한다. 02 FR-H9는 사용하면서 이 내용으로 개정한다.

```text
[붙여넣기 칸]  AI가 만든 경력기술서·자기소개서 원문
     ☑ 근거 ID 지우기      (E-001), (E-001, E-010), (프로필, E-001) 같은 괄호
     ☐ 익명화 되돌리기     A사 → 가나철강 …
     ☐ [메모] 절 지우기     프롬프트 v0.2가 만든 "[메모] …" 절 이하
[결과 칸]      정리된 텍스트 + 복사 버튼
               지운 괄호 n개, 되돌린 자리표시자 n개
```

- 근거 ID 패턴: `\s?\((?:프로필|E-\d{3,})(?:,\s*(?:프로필|E-\d{3,}))*\)`. 실험 01 출력 9회에서 나온 모양을 모두 지운다. `(2019)`·`(C-01)` 같은 다른 괄호는 건드리지 않는다.
- 처리는 브라우저 안에서 한다. 서버로 보내지 않고 **아무 데도 저장하지 않는다.**
- 한국어 오타 교정은 하지 않는다(R-10).

## 8. 시험

시험 자료에는 실데이터를 쓰지 않는다. 실험 01의 경험 구조(27건, 경력 5개, 과제 13개, 정량 성과 19개)를 본뜬 **가상 경력 vault**를 따로 만든다(02 §12 미결 해소).

| 시험 | 기준 |
|------|------|
| 직렬화 스냅샷 | 가상 vault를 고정 옵션으로 내보내 `exported_at` 줄을 뺀 결과가 저장된 스냅샷과 같다 |
| 범위 | 경력·기간·선택 범위마다 포함 경험 ID 집합이 기대값과 같다. 기간 경계(겹침) 포함 |
| 상태 | `초안`은 어떤 옵션에서도 0건 |
| 빈 필드 | 빈 필드 줄이 없다. `역할·구분·상태`는 항상 있다 |
| 익명화 | 치환 뒤 모든 `from`이 0회. "가나철강의"·"Gana Steel's"가 바뀐다. `E-001`은 그대로 |
| 잔존 경고 | `from` 하나를 일부러 빼면 경고가 뜬다 (일부러 깨뜨리기) |
| 결과물 정리 | 근거 ID 괄호 모양 9가지(실험 01 출력에서 수집)가 모두 지워지고 `(2019)`는 남는다 |
| 프롬프트 | 목적 A·B·C와 JD 유무 6조합이 use_context_file.md v0.2 문구와 같다 |
| 크기 경고 | 10만 자·30만 자 경계 |

## 2. 경력기술서 분해 결과 (익명화 요약)

원문은 A4 약 5장, 역량별(L1~L5) 재구성 형식의 팀장급 경력기술서. 분해 결과:

| 항목 | 수 |
|------|----|
| 경력(Career) | 5 (한 회사, 조직·직위 변경 5회) |
| 과제(Project) | 11 |
| 경험(Experience) | 25 (업무 21, 업무 외 4) |
| 그 중 상황·행동·결과가 모두 채워진 것 | 12 |
| 그 중 이름만 나오고 내용이 빈 것 | 6 (수상·발표 안건·대표 과제 목록에만 등장) |
| 정량 성과 | 19 (비교 기준 있음 5, 없음 14) |
| 역량 태그 | 25 (기술 8, 업무 7, 리더십 6, 문제해결 4) |
| "확인 필요" 질문 | 약 50 |

## 3. 분해하며 발견한 것 (형식·프롬프트·파서에 반영함)

1. **같은 사실이 3~4곳에 반복된다.** Snapshot 표, 경력 요약, 역량 상세, 첨부 요약에 같은 수치(115명, 85%, 44%)가 나온다. 분해 프롬프트에 "가장 상세한 서술을 기준으로 합치고 다른 곳의 수치를 보탠다" 규칙을 넣었다. 파서는 같은 제목·기간의 블록을 중복 후보로 표시해야 한다.
2. **기간이 연 단위다.** 월이 있는 항목은 입사월 하나뿐. 일부 경험은 기간 자체가 없다(6개월짜리 실패 과제, 교류회, 연구회). 기간 필드는 `YYYY`, `YYYY-MM`, `YYYY ~ YYYY`, `확인 필요`를 모두 받아야 한다.
3. **비교 기준이 없는 수치가 다수다.** 19개 중 14개. "115명 육성", "16건 수행", "11건 발표"는 누적 수치지 개선 수치가 아니다. AI가 여기에 "개선"을 붙이면 사실이 아니게 된다. 정량 성과를 `지표 | 값 | 기준 | 시점` 네 칸으로 나누고 "기준 없음"을 명시하게 했다. 사용 안내문에도 같은 규칙을 넣었다.
4. **역할이 불명확한 과제가 있다.** 수상 목록과 발표 안건에만 나오는 과제 3건은 본인이 수행자인지, 리더인지, 발표자인지 알 수 없다. 분해 프롬프트 규칙 5로 "빈 경험으로 만들고 역할을 질문"하게 했다.
5. **횡단 경험이 있다.** "경영층 직접 발표 11건 (2018~2026)"은 여러 과제에 걸친다. 개별 발표를 각 과제 경험에 흩어 넣으면 "경영층 커뮤니케이션" 역량의 근거가 사라진다. 횡단 경험 하나로 두고 행동에서 관련 경험을 참조하게 했다. 데이터 모델에서 경험 간 참조(E-009 → E-002)를 허용해야 한다.
6. **한 줄에 과제 여러 개가 묶인 경우가 있다.** "대표 과제: A / B / C". 쪼갤지는 사용자 판단이므로 프롬프트에 "임의로 쪼개지 않고 질문"하게 했다.
7. **"교훈" 서술이 STAR 어디에도 안 들어간다.** "▶ 운영 원칙", "▶ 위임에서 확인한 것" 같은 블록이 5개 있고, 팀장급 문서에서는 이 부분이 설득의 핵심이다. 경험 모델에 **교훈** 필드를 추가했다. 01_PRODUCT_CONCEPT 5장 모델에는 없던 것이다.
8. **업무 외 활동도 경험이다.** 개인 앱 개발, 연구회 회장이 역량 근거로 쓰인다. **구분(업무/업무 외)** 필드를 추가했다.
9. **학위·특허·수상·자격은 경험이 아니라 프로필과 증빙이다.** 특허는 관련 경험의 증빙으로 연결하고, 프로필에 목록을 둔다. 어느 특허가 어느 과제 것인지는 문서만으로 알 수 없었다 (확인 필요).
10. **크기.** 25건에 약 22,000자(프로필·표 포함). 경험당 평균 700~900자. 한국어는 1자당 1토큰 안팎이므로 1건에 500~800 토큰이라는 00_PREPARATION의 가정과 비슷하거나 약간 크다. "확인 필요"와 "교훈"이 더해진 영향. 100건이면 9만 자 안팎이라 당장 분할은 불필요하지만, 본문 붙여넣기 경로에서는 한도에 걸릴 수 있어 실험 4.3에서 확인한다.
11. **분해 자체가 "질문 생성기"다.** 약 50개의 "확인 필요"가 나왔고, 대부분 "이 수치의 기준은?", "이 과제에서 본인 역할은?", "기간의 월은?" 세 유형이다. 구조화 프롬프트의 후속 질문 규칙을 이 세 유형 우선으로 정했다.

#### 4.1.1 ChatGPT × A 관찰 (2026-11-01)

- 수치 19개 전부 보존. "기준 없음" 수치에 비교 표현 없음, 기준 있는 수치에만 "개선·단축". 사용 안내문의 기준 규칙이 작동함.
- 작은 사실 추가 3곳: "매주 보고 대상" → "매주 경영층 보고 대상", "Mac 없이" → "Windows 기반 개발 환경", 요약에 "사업화". 성과를 만들지는 않았으나 맥락을 보탬.
- "확인 필요"가 많은 빈 경험 6건은 전부 제외됨 (올바른 동작). 그러나 특허 3건도 "어느 과제 것인지 확인 필요"를 이유로 통째로 빠졌고 프로필의 특허 목록도 안 씀. 횡단 경험 E-009(경영층 발표 11건)도 빠짐.
- 본문에 "기간: 세부 기간 확인 필요"를 그대로 적음. 미확정을 단정하지 말라는 규칙의 부작용.
- 형식: 요약·역순·근거 ID·했다체 준수. "넣을지 물어볼 경험" 목록과 "데이터 확인 요청" 절은 생략. 분량은 A4 2~3장 지시를 넘음 (경험 13건).
- 근거 ID 괄호는 채점 속도를 크게 높임. 검증 장치로 유지.

v0.2 반영 후보: ① 프로필(특허·수상·학력)은 그대로 쓰라고 명시 ② 횡단 경험은 역량 근거로 반드시 언급 ③ 기간 미상이면 연도만 쓰고 "확인 필요" 문구를 본문에 넣지 않음 ④ 분량은 장 수가 아니라 경험 개수로 제한 ⑤ "넣을지 물어볼 경험" 목록을 출력 형식 절로 이동.

#### 4.1.2 ChatGPT × B 관찰 (2026-11-01)

- 사실·수치 모두 보존. 없는 내용을 만든 곳 없음. 교훈 필드를 각 이야기의 마지막 문장으로 거의 그대로 사용.
- 미확정 역할(E-004)을 추정하지 않고 본문에 `[질문: …]`을 남기고 계속 씀. "불확실할 때" 규칙이 작동. 다만 문장 안에 들어가 "…입니까?]로 확인이 필요합니다"처럼 어색함.
- A에서 빠진 E-004(실패), E-006(Pool)을 살림. "관련 경험 2개 이상인 역량 우선" 지시의 효과.
- 분량(근거 ID 제외): 절별 공백 제외 777 / 744 / 874자, 전체 2,480자. 공백 포함은 1,004 / 958 / 1,134, 전체 3,208자. 지시(절 600~800, 전체 2,000~2,400)에 공백 기준이 없어 판정 불가. 공백 포함 기준이면 30% 초과.
- "선택한 역량 3개와 이유를 본문 앞에 3줄" 누락. A의 "넣을지 물어볼 경험" 누락과 같은 패턴: 출력 형식 절 밖에 둔 출력 지시는 빠지기 쉬움.

v0.2 반영 후보: ① 분량은 "공백 포함"으로 명시하고 절당 상한 강조 ② "역량 3개와 이유"를 출력 형식 절 첫 항목으로 이동 ③ `[질문]`은 문장 안이 아니라 문단 끝 별도 줄에.

#### 4.1.3 ChatGPT × C 관찰 (2026-11-01)

- 질문 15개가 유형별 5·3·3·4로 정확히 분배. 질문마다 네 요소(질문/이유/근거 3줄/약한 지점) 모두 갖춤. 요청하지 않은 "수치 확인 우선순위" 표와 총평이 추가됐으나 누락은 없음.
- 근거 45줄과 표 전부 파일 사실. 갈등 사례가 파일에 없음을 약한 지점으로 명시 (규칙 준수).
- "확인 필요" 필드가 그대로 "약한 지점"과 "준비가 부족한 경험" 표(14건, 우선순위 포함)로 변환됨. 빈 경험 6건을 삭제하지 않고 질문으로 남긴 설계가 활용 단계에서 가치를 냄. D-010 후보의 근거.
- 수치 검증 질문은 비교 기준이 없는 수치(30개 팀·50명, 30여 건, 16건)를 정확히 골라 집계 기준을 물음. 정량 성과 네 칸 분리의 효과.
- 횡단 경험 E-009는 질문에 쓰이지 않고 "준비 부족" 목록으로 감. A·B·C 모두 같은 패턴. 횡단 경험의 취급을 형식 차원에서 정해야 함.
- A·B와 달리 형식 만점인 이유: 출력해야 할 항목이 전부 "형식" 절에 열거되어 있었음.

#### 4.1.5 Gemini × A 관찰 (2026-11-01)

- 수치 전부 보존, 기준 없는 수치에 비교 표현 없음 (2회 서비스 연속 만점).
- 사실 어긋남 3곳: E-020 "전 과정을 직접 구현"(파일: 기획·검증, 구현은 AI 코딩 도구) / E-001 특허 3건을 정량 성과로 단정(파일: 확인 필요) / 요약에서 "총 10년 이상 경력(현대제철 8년 6개월)"로 두 수치를 섞음.
- **같은 미확정 항목(특허 3건)을 ChatGPT는 삭제, Gemini는 단정.** 확인 필요 항목의 처리는 서비스별로 갈리므로 프롬프트보다 파일에서 해결(사용자가 답을 채움)하는 것이 확실함.
- 경험 10건만 사용 (ChatGPT 13건). 빈 경험 6건 제외는 정상. 그러나 E-018(권한 위임, 내용 완전)과 업무 외 경험 전부를 말없이 제외. "넣을지 물어볼 경험" 목록 없음 → 사용자가 누락을 알 수 없음. E-009 횡단 경험 4회 연속 누락.
- 프롬프트 라벨 "역할 한 줄"을 글자 그대로 출력. 형식 지시에서 라벨과 설명을 분리해야 함.
- 분량은 ChatGPT보다 간결해 A4 2~3장에 가까움.
- **복사 손실**: Gemini 웹 응답을 복사하면 글머리표가 U+FFFC("￼")로, "2025~2026"의 물결표가 사라져 "20252026"으로 들어옴. 활용 문서는 눈으로 고치면 되나 구조화 왕복(4.2)에서는 파서 입력이 깨짐. Gemini × decompose_cv 실험에서 확인 필수. 4.3 표에 기록.

#### 4.1.6 Gemini × B 관찰 (2026-11-01)

- 분량(근거 ID 제외): 공백 제외 566 / 670 / 484, 전체 1,808자. 공백 포함 739 / 876 / 620, 전체 2,357자. 공백 포함 기준으로 범위 안 (ChatGPT는 3,208자).
- "역량 3개와 선택 이유"를 본문 앞에 씀 (ChatGPT는 누락). 형식 절 밖의 지시는 서비스마다 처리가 다름 → 형식 절로 옮기면 양쪽 해결.
- 미확정 역할(E-004)을 본인 주도로 단정. `[질문]` 표시 없음 (ChatGPT는 표시함). 특허 3건도 단정. **Gemini는 "확인 필요"를 일관되게 무시(A·B 3회)**, ChatGPT는 삭제하거나 질문. 대책은 프롬프트가 아니라 사용자가 파일의 확인 필요를 채우는 것.
- 꾸밈말: "뼈아픈 결론", "귀중한 레슨런", "전면 전환". 감정·강조 금지 규칙 일부 위반. "PBL(Problem-Based Learning)" 확장은 파일에 없는 추정.
- 문서 끝에 대화용 안내 문장("…준수하여 작성하였으며…")이 붙음. 출력 형식에 "문서 외 문장 금지"를 넣을 것.

#### 4.1.7 Gemini × C 관찰 (2026-11-01)

- 15개 질문 5·3·3·4 분배, 네 요소 모두 갖춤, 준비 부족 목록 있음. 수치 검증 질문이 확인 필요 항목(44% 측정 방식, 리드타임 시점, 반려 건수)을 정확히 겨냥.
- 작은 창작 4곳: Q3 "직접 구현"(A와 동일 오류) / Q14 "수요 증명 기반 안건 기획을 고수함"(E-004 교훈을 11건 발표의 원칙으로 일반화) / Q2 "50명을 설득" / Q11 "팀장 부임 초기". 오타("공공 벤치마크", "저효과 과를")와 이모지.
- **횡단 경험 E-009가 처음으로 사용됨** (Q14). E-018, E-022, E-023도 질문에 포함. ChatGPT C보다 넓게 훑음.
- 준비 부족 목록 5건 (ChatGPT 14건). 가장 비어 있는 E-021을 빠뜨림 (Q5에서 인용해 놓고 목록에서 제외).

#### 4.1.8 Gemini 소계

| 프롬프트 | 사실 | 수치 | 형식 | 제출 |
|----------|------|------|------|------|
| A | 1 | 2 | 1 | 1 |
| B | 1 | 2 | 2 | 1 |
| C | 1 | 2 | 2 | 1 |

수치 보존 3회 만점 (ChatGPT와 동일). 형식은 ChatGPT보다 약간 나음. 사실 정확성은 3회 모두 1점이며 유형이 같음: ① 확인 필요 단정 ② 역할 격상(기획·검증 → 직접 구현) ③ 교훈의 원칙화. 대책은 프롬프트 금지 문구 강화보다 파일 쪽: 구현 주체를 역할 줄에 명시, 확인 필요 답 채움.

#### 4.1.9 Claude × A 관찰 (2026-11-01)

- 9회 중 유일하게 모든 출력 지시 준수: 요약 3역량, 역순, 필드, 문장마다 근거 ID, **"넣을지 물어볼 경험" 12건(이유 포함)**, **"데이터 확인 요청" 8건**. 프로필(학력·특허·수상) 별도 절. 분량만 A4 2~3장 초과. 한국어 오타 4개(가늄·없앰다·커파·컨고).
- 사실 추가 없음. 구현 주체를 역할 줄에 정확히 기재. 특허는 크랙 2건만 E-001에 연결, 래들 특허는 프로필에만. 포상 명칭 불일치는 "연구개발본부 포상"으로 보수 처리.
- **횡단 경험 E-009를 A에서 사용한 첫 사례.** 요약에 "경영층 11건 직접 발표"를 넣고 각 경험에 흩어 넣음. 처리 방식을 "넣을지 물어볼 경험"에 설명.
- "확인 필요" 처리의 세 번째 유형: ChatGPT 삭제 / Gemini 단정 / **Claude 보수 기재 + 보고**. 사용자가 다음에 채울 것이 바로 보임.
- 스마트팩토리기술팀 6년을 직위별(C-02·C-03·C-04) 세 묶음으로 분리. 경력 표 C-ID를 그대로 따름.
- **"데이터 확인 요청" 8건은 실데이터 파일의 실제 오류** (수작업 분해 때 놓침): ① 총 경력 8년 6개월 vs 계산 8년 9개월 ② C-04·C-05 기간 겹침 ③ E-002의 2019년 발표 vs 2019년 소속 C-01 ④ E-003 기간(2020~) vs 2018 포럼 ⑤ E-005 기간(2023~24) vs 2025 발표 ⑥ 래들 특허의 E-001 귀속 ⑦ 2019 포상 명칭 3종 ⑧ E-018 소속. → 앱의 "확정" 단계에 **정합성 검사**(기간 겹침, 소속·연도 불일치, 같은 사실의 명칭 불일치) 요구사항으로 02_REQUIREMENTS에 반영할 것.

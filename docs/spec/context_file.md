## 1. 용어 (D-012)

| 영문 | 한국어 | 비고 |
|------|--------|------|
| Career | 경력 | 회사 / 조직 / 직위 / 기간. ID `C-nn` |
| Project | 과제 | 선택 계층. ID `P-nn` |
| Experience | 경험 | STAR 단위. ID `E-nnn` |
| Entry | 기록 | 사용자가 쓴 원문. 경험의 재료 |

STAR의 T는 "과제"가 아니라 **"목표"**로 부른다. Project의 한국어 이름 "과제"와 겹치기 때문이다. (D-012 확정)

## 2. 컨텍스트 파일 (앱 → AI)

### 2.2 사용 안내문 (파일 상단 고정)

실험 01에서 세 서비스 모두 이 안내문의 수치 규칙을 지켰다 (9회 모두 수치 보존 만점). 근거 ID 규칙도 세 서비스가 지켰고 채점 시간을 크게 줄였다.

```markdown
- 이 문서는 사용자가 직접 기록하고 검토한 경력 데이터다.
- 여기에 없는 성과, 수치, 역할, 직위를 만들지 않는다.
- 수치는 문서에 적힌 값과 비교 기준만 사용한다. "기준 없음"으로 표시된 수치는 비교 표현(개선, 단축, 증가)을 붙이지 않는다.
- 추정이 필요하면 문장을 만들지 말고 사용자에게 질문한다.
- 요청받은 문서 형식을 따르되, 각 문장은 아래 경험 ID 중 하나에 근거해야 한다. 결과물에는 근거 ID를 괄호로 남긴다. 예: (E-001)
- "확인 필요" 항목에 적힌 내용은 미확정이다. 그 내용을 단정하는 문장을 쓰지 않는다.
```

근거 ID는 최종 문서에서 사용자가 지워야 한다. 앱의 내보내기 화면에 "결과물에서 (E-nnn) 일괄 삭제" 안내 또는 도구가 필요하다.

### 2.4 크기

실데이터 25건 기준 약 42KB(약 22,000자, 프로필·표 포함). 경험 1건 평균 700~900자. 100건이면 9만 자 안팎이라 ChatGPT·Claude·Gemini의 파일 첨부 한도 안이다. 분할은 v0.1에서 다루지 않는다.

## 3. 구조화 응답 블록 (AI → 앱)

사용자가 AI 응답을 앱에 붙여넣으면 앱이 이 블록을 찾아 파싱한다. 기록 1건 구조화(`docs/prompts/structure_entry.md`)와 경력기술서 분해(`docs/prompts/decompose_cv.md`) 모두 같은 형식을 쓴다.

### 3.1 형식

````markdown
```slow-way
형식: slow-way-experience/0.1
제목: 포장 라인 외관 불량 실시간 판정 모델 개발
````

### 3.2 규칙 (프롬프트에 그대로 들어감)

1. 블록은 반드시 ` ```slow-way ` 로 시작하고 ` ``` ` 로 끝낸다. 블록 밖의 설명은 자유롭게 써도 되며 앱은 무시한다.
2. 첫 줄은 `형식: slow-way-experience/0.1`.
3. 한 줄에 `키: 값`. 키는 위 목록의 이름만 쓴다. 값이 없으면 키만 남기고 비운다. 키를 빼지 않는다.
4. 목록 키(행동, 결과_정량, 증빙, 확인_필요)는 다음 줄부터 `- ` 로 시작하는 항목을 나열한다.
5. `결과_정량` 항목은 `지표 | 값 | 기준: … | 시점: …` 네 칸을 `|` 로 나눈다. 비교 기준을 모르면 `기준 없음`이라고 쓴다. 원문에 없는 수치를 만들지 않는다.
6. 원문에 없는 내용은 추정하지 않는다. 비어 있으면 `확인_필요`에 질문으로 적는다.
7. 경험이 여러 개면 블록을 여러 개 쓴다. 블록 하나에 경험 하나.

**선택 키 `과제:` (v0.3)** — 사내 과제 기록으로 만든 프롬프트일 때만 `과제: <과제 번호>` 한 줄을 `제목:` 앞에 둘 수 있다. 다른 프롬프트는 쓰지 않는다. 느린 나이테는 아직 프롬프트에 넣지 않았고 미리보기에서 과제를 추정한 뒤(이어짐 경험의 과제 → 고른 과제가 하나 → 제목) 사람이 고른다. 실험 2차(과제 셋·블록 다섯)에서 과제를 못 정한 블록이 0건이라 급하지 않다. 넣을 때는 이 절을 기준으로 느린 나이테 프롬프트를 고친다.

### 3.3 파서 규칙 (v0.3. v0.2는 실험 01 4.2로 확정, v0.3은 느린 나이테 구현으로 보강)

실험 01에서 ChatGPT 20블록, Gemini 7블록, Claude 21블록을 사람이 파싱한 결과를 반영했다. 모든 블록이 아래 규칙으로 읽혔다.

**블록 찾기**
1. 블록 시작은 `형식: slow-way-experience/0.1` 줄이다 (앞뒤 공백·펜스 무시). 다음 `형식:` 줄 직전까지가 한 블록. **펜스(```slow-way)는 있으면 보조로 쓰고, 없어도 동작한다.** ChatGPT는 펜스를 출력하지 않았고 Claude만 지켰다.
   - **v0.3 보강**: 펜스가 열렸으면 **닫는 펜스까지**가 블록이다. 펜스가 없으면 다음 `형식:` 줄, 또는 **빈 줄 뒤에 키도 목록도 아닌 줄**에서 끝난다(그 뒤는 블록 밖 설명이라 무시). 실험 2차의 Teams Copilot도 펜스를 내지 않았다.
2. 블록을 하나도 못 찾으면 응답 전체를 Entry 원문으로 보존하고 "형식 블록이 없습니다. 프롬프트를 다시 붙여넣으세요"를 안내한다.

**전처리**
3. 각 줄 끝의 Gemini 인용 표식 `\[span_\d+\]\((start|end)_span\)` 을 제거한다. Gemini 복사 버튼이 첨부 파일 근거 표식을 그대로 내보낸다.
4. U+FFFC(``) 등 제어·치환 문자를 제거한다 (Gemini 글머리표 손실).
   - **v0.3 보강**: **줄머리**의 U+FFFC는 지우지 않고 `- `로 되돌린다(깨진 글머리표). 줄 중간의 것만 지운다.
5. 줄 단위 파서. YAML·JSON 라이브러리를 쓰지 않는다. 한국어 값에 콜론·따옴표·`#`이 흔하다.

**키와 값**
6. 키는 줄의 첫 `:` 앞. 비교는 공백·밑줄을 지우고 한다 (`결과 정량` = `결과_정량`). 모르는 키는 버리지 않고 "미분류"로 보관해 보여 준다.
   - **v0.3 보강**: 첫 `:` 앞을 정규화한 것이 **알려진 키**이거나, **8자 이하·공백 하나 이하·문장부호 없음**일 때만 키로 본다. 그 밖은 키가 아니다(예: "단, 기준은 바뀔 수 있음: …"은 값의 이어지는 줄).
7. 스칼라 키(상황, 목표, 결과_정성, 비즈니스_영향, 역량_*, 교훈) 아래에 `- ` 목록이 와도 받아서 줄바꿈으로 결합한다. 교훈의 `/` 결합과 출처 표시 "(L3 부제)"는 그대로 보존한다.
   - **v0.3 보강**: 키도 목록도 아닌 줄은 **빈 줄 전까지 바로 위 칸의 값에 이어 붙인다**(긴 값을 두 줄로 쓴 것). 규칙 13(안 읽히는 줄)은 그 밖의 줄에만 적용한다.
8. 빈 값 정규화: 빈 문자열, `-` 단독, `해당 없음`, `미상`, `없음`, `확인 필요`는 모두 빈 값으로 저장하되 원문 표기는 보존한다.
   - **v0.3 보강**: `결과_정량`의 **값·시점 칸**에도 같은 빈 값 표기를 적용한다(`시점: 확인 필요`).
9. `이어짐: E-nnn` / `E-nnn?` / `없음` 을 인식한다 (structure_entry 전용).

**정량 성과**
10. `결과_정량` 항목은 `|`로 나눈다. 4칸이면 지표·값·기준·시점. 3칸이면 시점 없음. 2칸 이하면 전체를 지표 칸에 넣고 경고.
11. 기준 칸의 `기준:` 접두어와 시점 칸의 `시점:` 접두어를 제거한다 (템플릿을 그대로 채운 결과 "기준: 기준 없음"이 흔함).
12. 기준 칸이 `기준 없음`·`미상`·빈 값이면 "기준 없음"으로 저장한다. 기준 칸에 "팀 정원", "연간 심의 건수", "7주간", "격주"처럼 집계 단위·조건·기간이 오면 확정 화면에서 "비교 기준인가?"를 묻는다 (R-05).

**오류 처리**
13. 줄이 안 읽히면 그 줄 번호와 원문을 보여 주고 나머지는 채운다. 블록 전체를 버리지 않는다.
14. 같은 응답 안에서 제목·기간·정량 수치가 유사한 블록 쌍을 중복 후보로 표시한다 (R-02).
    - **v0.3 보강**: "유사" = 공백·문장부호를 지운 제목이 같거나 유사도 0.8 이상, **또는** 기간이 같고 정량 값 하나가 같음.
15. 파싱 결과와 함께 원문 응답 전체를 Entry로 보존한다.

**값 읽기 (v0.3 추가)**
16. **기간**: `YYYY-MM ~ YYYY-MM` 밖에 `YYYY ~ YYYY` · `YYYY.MM-YYYY.MM` · `YYYY/M` · `YYYY년 M월 ~ M월` · 물결표 없는 두 날짜 · 끝이 `현재`·`진행 중`인 것을 읽는다. 날짜가 하나면 시작 = 끝.
17. **교훈 출처**: 교훈 끝의 괄호 출처 "(…)"는 `lesson_source`로 따로 두되, 교훈 원문은 그대로 둔다.
18. **기준 종류 추정**: 기준 칸의 낱말로 `baseline_kind` 후보를 낸다. 비교: 대비·기존·전년·이전·→·비교·보다 / 집계: 누적·연간·총·정원·건수·합계·월간·평균 / 조건: 가정·조건·환산·주간·격주·개월·기간. **확정은 사람이 한다**(추정은 제안일 뿐).

## 1. 질문

D-006은 iOS 원안을 버리고 느린 나이테와 같은 로컬 웹 도구로 정했다. 묶음 A(골격 복사)에 착수하면 이 선택을 되돌리기 비싸진다. 지금 다시 본다.

검토할 안은 세 가지다.

| 안 | 내용 |
|----|------|
| **A. 로컬 웹 유지** | D-006 그대로. 개인 PC에서 `run.bat`, 1093px 데스크톱 |
| **B. 아이폰 앱으로 전환** | 01 원안으로 복귀. SwiftUI, 데이터는 기기(또는 iCloud) |
| **C. 단계적 결합** | M0·M1은 A. 폰에서는 "기록만" 가볍게 받는 통로를 둔다. 아이폰 앱은 M1 지표를 보고 M2에서 판단 |

## 2. 무엇이 플랫폼을 가르는가

느린 길의 일은 성격이 다른 두 종류다.

| 일 | 시나리오 | 길이 | 어울리는 기기 |
|----|----------|------|---------------|
| **기록** | S2 한 줄 기록 (2분) | 짧고 자주, 일이 생긴 그 자리에서 | **폰**이 유리 |
| **정리·활용** | S1 경력기술서 분해(30분), S3 주말 정리(10분), S4·S5 내보내기, S6 이동 | 길고 드물게, 앉아서 | **PC**가 유리 |

- 01 원안이 아이폰을 고른 이유는 "기록"이다(01 §6 음성·메모, §13.2 "새 업무 발생 → 앱 실행").
- D-006 이후 설계와 실험 01은 "정리·활용"에 집중했다. M0의 끝나는 조건(S1을 앱만으로)도 정리·활용 쪽이다.
- 그래서 두 안 중 하나가 일방적으로 낫지 않다. **어느 쪽 가설을 먼저 검증하느냐**의 문제다.

## 3. 시나리오별 비교

| 시나리오 | A. 로컬 웹 | B. 아이폰 |
|----------|------------|-----------|
| S1 경력기술서 분해 | 좋음. 5장 붙여넣기, 20여 블록 검토, 탭 전환으로 프롬프트 왕복 | 나쁨. 긴 글 붙여넣기·20여 건 검토가 작은 화면에서 길다. 앱 전환 왕복 마찰 큼 |
| S2 한 줄 기록 | **약함.** PC 앞에서만. 1차 페르소나는 사내 PC 인터넷 차단, vault는 개인 PC(D-009) → 근무 중 기록이 어렵다 | **좋음.** 언제든. 음성 받아쓰기는 iOS 키보드 기본 기능으로 거의 공짜 |
| S3 주말 정리 (구조화 왕복) | 좋음 | 보통. AI 앱과 오가며 복사·붙여넣기. 펜스 없는 응답 복사 품질은 iOS에서 미검증 |
| S4·S5 내보내기 | 좋음. 파일 첨부 실험 01에서 검증됨(웹) | 미검증. iOS 공유 시트로 .md를 AI 앱에 넘길 수 있는지 실험 01 §4.3 표가 비어 있다 |
| S6 데이터 이동·백업 | 좋음. 폴더째 복사 | 보통. 내보내기 zip 또는 iCloud |

**발견한 빈틈 (A안)**: S2 "2분 기록"은 02 §9의 핵심 지표(4주 후 주간 기록 비율 50%)와 직결되는데, A안의 1차 페르소나는 일하는 동안 앱에 닿을 수 없다. 퇴근 후 개인 PC에서 몰아 쓰게 된다. 이 빈틈은 지금 문서 어디에도 대응이 없다.

## 4. 만드는 비용과 위험

| 항목 | A. 로컬 웹 | B. 아이폰 |
|------|------------|-----------|
| 재사용 | 느린 나이테 골격·안전망·배포 도구(05 §2). 묶음 A가 바로 시작 가능 | 거의 없음. 파서·직렬화·익명화·정합성(순수 함수)을 Swift로 다시 작성 |
| 그대로 쓰는 문서 | 전부 | 02·04의 데이터 모델, 파일 형식 스펙, 프롬프트, 실험 결과는 그대로. 03 UX(1093px), 05 기술 설계, NFR-01~03·09·11은 다시 쓴다 |
| 개발 환경 | 리눅스·윈도우 어디서나. 이 클라우드 세션에서 빌드·시험·화면 시험까지 가능 | **Mac + Xcode 필수.** 이 클라우드 세션(리눅스)에서는 Swift 코드를 쓸 수는 있어도 빌드·실행·시험은 못 한다. 확인은 전부 개발자 Mac에서 |
| 배포 | ZIP. 심사 없음 | Apple Developer Program 연회비(유료), TestFlight로 베타, App Store 심사. 개인정보 처리방침 필요 |
| 무료 전용(D-005) | 운영 비용 0 | 사용자에게는 무료로 낼 수 있으나 개발자 연회비가 생긴다 |
| 외부 요청 0(NFR-03) | 지킴 | 지킬 수 있음(온디바이스 저장). iCloud 동기화를 쓰면 데이터가 Apple 서버를 거친다 |
| 시리즈 일관성 | 느린 나이테와 같은 스택·운영 | 갈라진다. 공통 코어 분리(05 §9)가 불가능해진다 |
| 일정 영향 | 08 로드맵 그대로 | 03·05 재작성 → 골격 신규 → M0 일정 크게 늘어남 |

## 5. 안별 평가

### A. 로컬 웹 유지
- 장점: 이미 검증된 경로(실험 01은 웹으로 진행), 재사용 최대, 이 세션에서 끝까지 만들고 시험 가능.
- 단점: S2 기록 빈틈. 01 원안의 "틈틈이 기록"이 사실상 "주말에 몰아서 기록"이 된다.

### B. 아이폰 앱으로 전환
- 장점: 기록 습관 형성에 가장 강하다. 음성 입력.
- 단점: M0의 핵심인 S1(분해)이 가장 불편한 기기로 간다. 재사용 0, Mac 필수, 실험 01의 iOS 항목이 하나도 검증되지 않았다(공유 시트, 복사 품질). 검증 안 된 가설 위에 다시 쓰는 셈이다.

### C. 단계적 결합 (권장)
- M0·M1은 A로 간다. 정리·활용 가설(이미 실험으로 강하게 지지됨)을 앱으로 빨리 검증한다.
- 폰 기록은 **앱을 만들지 않고 통로만** 둔다. 후보:

| 통로 | 방식 | 원칙과의 충돌 | 판단 |
|------|------|---------------|------|
| **C-1. 메모 묶음 붙여넣기** | 폰 기본 메모·"나에게 보내기" 등에 날짜와 함께 적고, 주말에 PC에서 한꺼번에 붙여 넣으면 날짜 줄 기준으로 기록 여러 건으로 나눠 저장 | 없음. 외부 요청 0 유지. FR-B8("다른 앱에서 가져오기" 제외)만 일부 개정 | **권장.** 파서 하나 추가 수준 |
| C-2. 폰 브라우저로 PC 앱 접속 | 같은 와이파이에서 PC 서버에 접속 | NFR-03(`127.0.0.1` 단독) 위반, PC가 켜져 있어야 함, 사내망 불가 | 제외 |
| C-3. 호스팅 PWA | 웹앱을 인터넷에 올림 | D-006·D-008·NFR-03 전부 위반 | 제외 |
| C-4. 기록 전용 아이폰 앱 (M2) | 폰은 기록만 써서 동기화 폴더에 `entries/*.md`로 떨어뜨리고, PC 도구가 읽어 정리 | D-009가 동기화 폴더를 피한 이유는 SQLite 색인 손상. 색인은 PC 로컬에 두고 기록 파일만 동기화하면 피할 수 있다 | M1 지표가 나쁠 때의 다음 수 |

- vault가 Markdown 파일(NFR-04)이라 C-4로 가는 길이 열려 있다. 지금 A로 시작해도 아이폰 쪽 문이 닫히지 않는다.

## 6. 다시 판단할 신호

| 신호 | 출처 | 의미 |
|------|------|------|
| 4주 후 주간 기록 비율 < 50% | 02 §9, 08 §5 위험 | 기록 빈틈이 실제로 문제 → C-4(기록 전용 앱) 검토 |
| 베타 테스터가 "폰으로 적고 싶다"를 반복 | M1 설문 | 같음 |
| C-1 메모 묶음 붙여넣기 사용 비율이 높음 | 로컬 카운터 | 폰 기록 수요가 있음 → C-4 근거 |
| S1·S3를 폰에서 하고 싶다는 요구 | M1 설문 | 낮을 것으로 예상. 나오면 B를 재검토 |

## 7. 권장

**C안.** D-006(로컬 웹)은 유지하고, 다음 두 가지를 더한다.

1. **D-014(안)**: 폰 기록은 M0에서 앱이 아닌 "메모 묶음 붙여넣기"(C-1)로 받는다. 02 FR-B8을 개정해 "날짜 줄로 나뉜 메모 여러 건을 한 번에 기록으로 저장"을 M0 또는 M1로 넣는다.
2. **08 로드맵 §5 위험**에 "근무 중 기록 불가(사내 PC 차단 + vault는 개인 PC)"를 추가하고, 대응을 C-1 → (지표 미달 시) C-4로 적는다.

묶음 A(골격·시험 자료·파서)는 어느 안이든 손해가 적다. 시험 자료와 파서 규칙은 B로 가도 그대로 옮겨 쓴다. 다만 B로 간다면 골격 복사(0번)는 하지 않는 것이 맞다.

## 8. 결론을 바꿀 수 있는 사실 (개발자 확인 필요)

| 질문 | B 쪽으로 기우는 답 |
|------|-------------------|
| 지금 업무 기록을 실제로 어디에 하고 있나 | 이미 폰 메모에 쓰고 있다 → C-1이 바로 맞고, 앱 수요도 크다 |
| 개발용 Mac이 있고 Swift 개발을 할 의향이 있나 | 없으면 B는 사실상 불가 |
| 사내 보안 규정상 업무 내용을 개인 폰에 적어도 되나 | 안 되면 폰 기록 자체가 위험 → A가 맞다 |
| 이 도구를 팀원·다른 사람에게 나눠 줄 계획인가 | 아이폰 사용자가 많고 PC 설치를 꺼린다면 B 가치가 커진다 |
| M0 일정(개발자 본인 사용)보다 기록 습관 검증이 먼저인가 | 그렇다면 B 또는 C-4를 앞당긴다 |

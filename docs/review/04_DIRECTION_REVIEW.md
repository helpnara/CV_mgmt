## 3. 어떻게 하나로 가나 (가장 큰 결정)

| 안 | 방식 | 장점 | 단점 |
|----|------|------|------|
| **A. 처음부터 느린 나이테 안에** | 느린 나이테 저장소에 "정리" 영역(화면·서비스·vault 폴더)을 TODO 번호로 쌓는다. 느린 길 저장소는 설계 문서만 | 중복 0. 실제 데이터로 바로 검증. 운영 방식(TODO·배포본·체크리스트) 그대로 | 운영 중인 사내 시스템(시험 930여 건)에 실험적 기능이 섞인다. 경험 모델·파서 같은 새 개념을 큰 코드베이스 안에서 다듬어야 한다 |
| **B. 도메인은 따로, 화면·저장은 나이테 안에** (권장) | 느린 길 저장소에서 **순수 도메인 패키지**(파서·경험 모델 검증·정합성·역량 매핑·직렬화·익명화)를 시험과 함께 만든다. 파일·DB·화면을 모르는 함수만. 다 되면 느린 나이테에 패키지째 넣고, 화면·서비스·vault는 나이테 안에서 TODO로 만든다 | 실험 01로 규칙이 정해진 부분을 운영 시스템 밖에서 안전하게 완성. 통합 비용이 "폴더 하나 옮기기" | 두 저장소를 오가는 기간이 생긴다 |
| C. 별도 앱으로 만든 뒤 합치기 | 05 원안대로 골격 복사, 독립 앱으로 M0까지, 나중에 병합 | 독립 실행으로 빨리 써 볼 수 있다 | 골격·색인·설정·안전망을 두 번 만든다. 병합 때 vault·스키마·설정을 다시 맞춰야 한다. "같은 일은 한 곳에"(나이테 교훈 ②) 위반 |

**B를 권하는 이유**
- 05 §3이 이미 `domain/`을 "파일·DB를 모르는 순수 함수" 층으로 분리해 두었다. 이 층은 독립 앱이든 통합이든 똑같이 쓴다.
- 골격 복사(묶음 A-0)가 필요 없어진다. 느린 나이테가 그 골격 자체다.
- 묶음 A의 1(가상 시험 자료)·2(파서)는 **그대로 살아남는다**.

## 4. 통합 시스템 안에서 느린 길이 맡는 일

느린 나이테에 이미 있는 것과 느린 길이 더하는 것을 가른다.

| 이미 느린 나이테에 | 느린 길이 더하는 것 |
|---|---|
| 과제, 진행일지, 보고, 담당·역할·담당 기간, 회고(내가 한 일·결과), 그 밖의 성과, 기술·도구, 중간 성과, `★성과` 일지, 교육·행사, 사람별 이력 화면, 나의 한 해, STAR 정리 프롬프트(복사만) | **경험(Experience) 단위의 정리**: 과제 하나에서 경험 여럿, 상황·목표·행동·결과·교훈·확인 필요 |
| | **구조화 왕복**: STAR 프롬프트의 AI 응답을 **되받아 파싱**해 경험으로 저장 (나이테는 복사에서 끝난다 — 프로파일 11절 ②) |
| | **역량 사전과 역량 매핑**: 팀원별 역량 축(기술·업무·리더십·문제해결) |
| | **정합성 검사·확정 상태**: 초안 → 구조화 → 확정 |
| | **입사 전 경력**: 경력기술서 분해(FR-D)로 나이테에 없는 과거를 팀원별로 |
| | **팀원별 내보내기**: 컨텍스트 파일(6절) |

## 5. 데이터 모델 개정 방향 (04 v0.2 초안)

| 엔티티 | 지금 | 바꿀 방향 |

| **사람** | 없음 (profile.md 하나) | 느린 나이테 명부의 사람. 경험·경력·역량은 모두 사람에 속한다 |
| Project(과제) | `P-nn` 자체 과제 | **느린 나이테 과제 번호를 그대로** 참조. 입사 전 과제만 자체 번호 |

| Experience(경험) | `E-nnn` | 사람별. `person`, 출처(나이테 과제 담당 / 분해 / 직접) |
| Entry(기록) | `N-nnnn` 자체 | 나이테 **진행일지·회고가 기록**이다. 자체 기록은 경력기술서·AI 응답 원문만 |
| 역량 | `skills.yaml` | 나이테 "기술·도구"를 역량_기술의 입력으로 |
| vault 위치 | 느린 길 vault 루트 | 나이테 vault 안 `people/<이름>/` 아래 (예: `people/<이름>/experiences/E-001.md`). 나이테의 사람 단위 폴더 원칙과 같다 |

## 6. "사내와 개인 둘 다"를 한 시스템에서

| 용도 | 어디서 끝나나 | 방법 |
|------|---------------|------|
| 사내(평가·역량 관리) | 시스템 안 | 팀원별 경험·역량 정리 화면, 평가 자료 프롬프트(나이테 "나의 한 해"와 합침) |
| 개인(커리어) | **시스템 밖** | 시스템은 팀원별 **업무 이력 파일**(07의 컨텍스트 파일, 중립 이름)을 만들어 팀원 본인에게 건넨다. 그 파일로 무엇을 만들지(경력기술서 등)는 팀원이 자기 AI에서 정한다. 구직용 프롬프트는 시스템 안에 두지 않는다(238 ④) |

이렇게 하면 시스템 안에는 사내 용어만 남고, 팀원은 회사를 떠나도 자기 이력을 파일로 갖는다. 다른 팀원의 정보는 그 사람 파일에만 들어간다.

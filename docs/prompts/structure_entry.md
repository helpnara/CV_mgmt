# 프롬프트: 기록 1건 구조화 (프롬프트 왕복)

> 용도: 사용자가 앱에 자유 기록(Entry)을 쓰면 앱이 이 프롬프트를 만들어 복사한다. 사용자가 본인 AI에 붙여넣고, 돌아온 `slow-way` 블록을 앱에 붙여넣으면 앱이 파싱해 경험 필드를 채운다 (D-008).
> 앱이 채우는 자리: `{기록 원문}`, `{기록 날짜}`, `{기존 경험 목록}`, `{역량 사전}`.
> 형식: `docs/spec/context_file_v0.1.md` 3절.
> 상태: 초안 v0.1.

---

```text
아래 "기록"은 내가 오늘 업무에서 겪은 일을 적은 것이다. 이것을 경험(Experience) 하나로 구조화해 달라.

## 규칙
1. 기록에 있는 사실만 쓴다. 없는 상황·행동·결과·수치를 만들지 않는다. 빈 칸은 비워 두고 "확인_필요"에 질문으로 적는다.
2. 질문은 "없음"이 정상 답변일 수 있는 열린 질문으로 쓴다. (좋음: "이 일의 결과를 보여 주는 수치가 있는가?" / 나쁨: "몇 % 개선됐는가?")
3. 질문은 3개 이내. 결과·수치·본인 역할 순으로 중요하다.
4. 수치는 기록에 있는 것만. 비교 기준이 없으면 "기준 없음"이라고 쓰고 "개선·단축·증가"를 붙이지 않는다.
5. 역량은 아래 "역량 사전"에 있는 이름을 우선 쓴다. 사전에 없으면 새 이름을 쓰되 "확인_필요"에 "새 역량: …"으로 적는다.
6. 아래 "기존 경험 목록" 중 이 기록이 이어지는 경험이 있으면, 블록 맨 앞에 "이어짐: E-nnn"을 한 줄 추가한다. 새 경험이면 "이어짐: 없음". 확실하지 않으면 "이어짐: E-nnn?" 처럼 물음표를 붙인다.
7. "교훈"은 기록에 교훈·원칙·느낀 점이 적혀 있을 때만 채운다.

## 출력 형식
- 아래 블록 하나만 출력한다. 블록 밖에 설명을 쓰지 않는다.
- 블록은 반드시 ```slow-way 로 시작하고 ``` 로 끝낸다.
- 키는 아래 이름만 쓰고, 값이 없어도 키를 빼지 않는다.
- 목록 키(행동, 결과_정량, 증빙, 확인_필요)는 다음 줄부터 "- "로 시작하는 항목을 나열한다.
- 결과_정량 항목은 "지표 | 값 | 기준: … | 시점: …" 네 칸을 | 로 나눈다.

## 실험에서 볼 것

- 입력 유형별 결과: 한 줄 메모 / 긴 서술 / 음성 전사체 / 반복 업무 / 진행 중 업무. 골든 세트 20~30개는 06_AI_DESIGN에서.
- 규칙 2(열린 질문)와 규칙 6(이어짐 판별)을 지키는 비율.
- 블록 하나만 출력하라는 지시를 어기고 앞뒤에 설명을 붙이는 빈도. 앱은 블록 밖을 무시하므로 치명적이지 않지만 복사 범위 혼란을 만든다.
- 기존 경험 목록과 역량 사전을 넣으면 프롬프트가 길어진다. 20건·100개 기준으로 서비스별 붙여넣기 한도에 걸리는지.

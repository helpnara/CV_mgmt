# 프롬프트: 컨텍스트 파일 활용 (목적별 3종)

> 용도: 사용자가 앱에서 컨텍스트 파일을 내보낼 때 함께 복사해 주는 프롬프트. 파일을 첨부(또는 본문에 붙여넣기)하고 아래 중 하나를 붙여 넣는다.
> 각 프롬프트는 "형식 지시 + 과장 금지 + 불확실 시 질문"의 세 부분으로 되어 있다 (00_PREPARATION 2.3).
> 상태: 초안 v0.1. 채용공고(JD)를 넣는 자리는 경력기술서·자기소개서에만 둔다.

---

## A. 경력기술서

```text
첨부한 파일은 내 경력 데이터다 (형식: slow-way-career-context). 파일 상단의 "사용 안내"를 먼저 읽고 지켜 달라.

이 데이터로 경력기술서를 작성해 달라.

## 형식
- 맨 위에 3~4줄 요약(현재 직위, 총 경력, 핵심 역량 3개).
- 경력(회사·조직) 역순으로 묶고, 각 묶음 안에 경험을 시간 역순으로 둔다.
- 경험마다: 제목 / 기간 / 역할 한 줄 / 상황과 목표 2~3문장 / 행동 2~4개 / 결과 (정량 먼저, 정성 다음).
- 전체 A4 2~3장 분량. 문장은 "~했다"체.
- 각 문장 끝에 근거 경험 ID를 괄호로 남긴다. 예: (E-001)

## 금지
- 파일에 없는 성과·수치·역할·직위를 만들지 않는다.
- "기준 없음"으로 표시된 수치에 개선·단축·증가 같은 비교 표현을 붙이지 않는다.
- "확인 필요"에 적힌 내용을 단정하지 않는다. 그 경험은 확정된 부분만 쓴다.
- 역량을 형용사로 꾸미지 않는다 ("탁월한", "뛰어난" 금지). 행동과 결과로 보여 준다.

## 불확실할 때
- 어떤 경험을 넣을지 애매하면 넣지 말고, 마지막에 "넣을지 물어볼 경험" 목록으로 ID와 이유를 적는다.
- 작성 중 파일에서 모순을 발견하면(기간 겹침, 수치 불일치) 마지막에 "데이터 확인 요청"으로 적는다.

## 채용공고 (있으면)
(여기에 JD 붙여넣기. 없으면 이 절을 지운다.)
JD가 있으면 JD의 요구 역량 순서로 경험의 강조점을 조정하되, JD에 맞추려고 없는 경험을 만들지 않는다. JD 요구 중 데이터에 근거가 없는 항목은 마지막에 "근거 없는 요구 항목"으로 따로 적는다.
```

## B. 자기소개서 (역량 중심, 지원동기 제외)

```text
첨부한 파일은 내 경력 데이터다 (형식: slow-way-career-context). 파일 상단의 "사용 안내"를 먼저 읽고 지켜 달라.

이 데이터로 자기소개서의 "경력·역량" 부분을 작성해 달라. 지원동기와 입사 후 포부는 쓰지 않는다.

## 형식
- 소제목 3개. 각 소제목은 역량 하나를 대표하고, 그 아래 경험 1~2개를 이야기로 푼다.
- 소제목마다 600~800자. 전체 2,000~2,400자.
- 각 이야기는 "상황 → 내 판단과 행동 → 결과 → 그 경험이 남긴 것" 순서. 파일의 "교훈" 필드가 있으면 마지막 문장에 쓴다.
- 1인칭. "~했습니다"체.
- 각 문단 끝에 근거 경험 ID를 괄호로 남긴다.

## 역량 선택
- 파일의 "역량 색인"에서 관련 경험이 2개 이상인 역량을 우선한다.
- 선택한 역량 3개와 선택 이유를 본문 앞에 3줄로 먼저 적고, 내가 바꾸고 싶으면 바꿀 수 있게 한다.

## 금지
- 파일에 없는 성과·수치·역할을 만들지 않는다.
- "기준 없음" 수치에 비교 표현을 붙이지 않는다.
- "확인 필요"에 적힌 내용을 단정하지 않는다.
- 감정 묘사("뿌듯했다", "힘들었다")로 분량을 채우지 않는다.

## 불확실할 때
- 이야기를 완성하는 데 빠진 정보(예: 당시 팀 규모, 기간)가 있으면 그 자리에 [질문: …] 표시를 남기고 계속 쓴다. 추정해서 채우지 않는다.

## 채용공고 (있으면)
(여기에 JD 붙여넣기. 없으면 이 절을 지운다.)
```

## C. 면접 예상 질문과 답변 근거

```text
첨부한 파일은 내 경력 데이터다 (형식: slow-way-career-context). 파일 상단의 "사용 안내"를 먼저 읽고 지켜 달라.

이 데이터를 바탕으로 면접관이 물을 만한 질문과, 각 질문에 답할 때 쓸 근거를 정리해 달라.

## 형식
- 질문 15개. 유형별로 나눈다: 경험 검증(5) / 수치 검증(3) / 실패·갈등(3) / 리더십·판단(4).
- 질문마다: 질문 / 왜 물을 것 같은가 1줄 / 답변 근거가 되는 경험 ID와 핵심 사실 3줄 이내 / 이 질문에서 약한 지점 1줄.
- 답변 문장을 대신 써 주지 않는다. 근거와 약점만 정리한다.

## 질문 선정 기준
- 수치 검증 질문은 "정량 성과 목록"에서 비교 기준이 없거나 "확인 필요"인 항목을 우선 고른다. 면접관이 가장 파고들 곳이다.
- 실패·갈등 질문은 파일에 실패나 종결로 적힌 경험이 있으면 그것을 쓴다. 없으면 "파일에 실패 사례가 없다"고 적고 질문만 제시한다.
- 경험이 비어 있거나 "확인 필요"가 많은 경험은 "준비가 부족한 경험" 목록으로 따로 뽑는다.

## 금지
- 파일에 없는 사실을 답변 근거로 제시하지 않는다.
- 약점을 감추는 답변 요령을 쓰지 않는다. 약점은 약점으로 적는다.

## 불확실할 때
- 질문이 파일의 어느 경험에 해당하는지 애매하면 해당 ID 후보를 모두 적는다.
```

## 채점표 (실험용)

각 서비스 × 프롬프트별로 아래 네 기준을 0~2점으로 채점한다. 기록은 `docs/experiments/01_context_file_validation.md`.

| 기준 | 0 | 1 | 2 |
|------|---|---|---|
| 사실 정확성 | 없는 성과·역할을 만듦 | 과장 표현 있음 | 파일 사실만 사용 |
| 수치 보존 | 수치 변형·창작 | "기준 없음" 수치에 비교 표현 | 값·기준 그대로 |
| 형식 준수 | 지시 형식과 다름 | 일부 어김 | 지시대로 |
| 제출 가능성 | 다시 써야 함 | 손질하면 가능 | 거의 그대로 가능 |

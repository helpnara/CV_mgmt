# 프롬프트: 기존 경력기술서를 경험 단위로 분해 (콜드 스타트)

> 용도: 온보딩에서 사용자가 기존 경력기술서·이력서 텍스트를 붙여 넣으면, AI가 경험(Experience) 후보를 `slow-way` 블록 여러 개로 돌려준다. 앱이 블록을 파싱해 "구조화" 상태의 경험 목록을 만들고 사용자가 하나씩 확정한다.
> 형식: `docs/spec/context_file.md` 3절.
> 상태: **v0.2** (2026-11-01, 실험 01 4.2 반영: ChatGPT·Gemini·Claude 분해 결과). 변경 내역은 문서 끝.

---

```text
아래 "경력기술서 원문"을 읽고, 경험(Experience) 단위로 분해해 달라.
경험 하나는 "특정 기간에, 특정 역할로, 어떤 상황에서, 무엇을 했고, 어떤 결과가 났는가"가 하나로 묶이는 단위다.

## 분해 규칙
1. 같은 사실이 요약·상세·수상·첨부에 여러 번 나와도 경험 하나로 합친다. 가장 상세한 서술을 기준으로 삼고 다른 곳의 수치를 보탠다.
2. 역량별·주제별로 재구성된 문서라도 결과는 시간순으로 정렬한다. 기간을 모르면 문서에 나온 연도 단서로 추정하되, 추정이면 "확인_필요"에 적는다.
3. 한 문단에 과제가 여러 개 묶여 있으면(예: "대표 과제: A / B / C") 하나의 경험으로 두고, "확인_필요"에 "과제별로 나눌지"를 적는다. 임의로 쪼개지 않는다.
4. 여러 시기에 걸친 횡단 활동(예: 경영층 발표 11건, 2018~2026)은 하나의 경험으로 두고, 개별 항목은 "행동"에 나열하면서 관련 경험 제목을 괄호로 적는다.
5. 이름만 나오고 설명이 없는 과제도 경험으로 만든다. 출처가 **수상 내역, 특허 목록, 경영층·대외 발표 안건, "대표 과제" 같은 과제 목록** 어디든 마찬가지다. 상황·행동·결과는 비워 두고 "확인_필요"에 "본인 역할, 상황, 성과 수치"를 적는다. 횡단 경험(규칙 4)의 행동에 나열한 과제도 각각 별도의 빈 경험으로 만든다. 수상·특허가 붙은 과제는 채울 가치가 크므로 빠뜨리지 않는다.
6. 학위, 자격, 논문 수, 어학연수는 경험이 아니다. 블록으로 만들지 말고 마지막에 "프로필 항목"으로 따로 정리한다.
7. 업무 외 활동(개인 프로젝트, 연구회, 동호회)은 경험으로 만들되 "구분: 업무 외"로 표시한다.
8. 원문의 "원칙", "교훈", "확인한 것" 같은 서술은 "교훈" 키에 원문 표현을 살려 넣는다. 요약하지 않는다.
9. 수치는 원문에 있는 것만 쓴다. 원문에 비교 기준이 없으면 기준 칸에 "기준 없음"이라고만 쓴다 ("기준: 기준 없음"처럼 접두어를 반복하지 않는다). "개선·단축·증가" 같은 말을 붙이지 않는다. 결과_정량에는 성과만 넣는다. 가정 조건("불량률 1%"), 주기("격주"), 소요 기간("6개월")은 성과가 아니므로 상황·행동에 쓴다.
10. 원문에 없는 내용을 추정해 채우지 않는다. 빈 칸은 비우고 "확인_필요"에 질문으로 적는다.
11. "역할"에는 본인이 직접 한 일과 다른 주체(팀원, 외부 기업, AI 코딩 도구)가 한 일을 구분해 적는다. 예: "기획·검증 담당, 구현은 AI 코딩 도구". 원문에 주체가 없으면 "확인_필요"에 "본인이 직접 수행했는지"를 적는다.

## 출력 형식
- 경험마다 아래 형식의 블록을 하나씩 쓴다. 블록 밖에는 설명을 쓰지 않는다 (마지막 "프로필 항목" 제외).
- 블록은 반드시 ```slow-way 로 시작하고 ``` 로 끝낸다.
- 키는 아래 이름만 쓰고, 값이 없어도 키를 빼지 않는다.
- 목록 키(행동, 결과_정량, 증빙, 확인_필요)는 다음 줄부터 "- "로 시작하는 항목을 나열한다.
- 결과_정량 항목은 "지표 | 값 | 비교 기준 | 시점" 네 칸을 | 로 나눈다. 비교 기준을 모르면 그 칸에 "기준 없음"을 쓴다.
- 경험이 10개를 넘으면 10개씩 나눠 출력하고 "계속"이라고 하면 이어서 출력한다. 마지막 묶음 뒤에 "분해 끝"이라고 쓴다.
- 같은 사실이 두 블록에 들어가면 안 된다. 출력 전에 수치(명, 건, %)가 두 블록에 겹치지 않는지 확인한다.

## 실험에서 볼 것

- 경험 수가 수작업 분해(25건)와 얼마나 다른가. 너무 잘게 쪼개는지, 합치는지.
- 규칙 1(중복 병합), 규칙 5(이름만 나온 과제), 규칙 9(기준 없음)를 지키는 비율.
- 블록 형식을 어긴 전형적 패턴 (키 이름 변형, `|` 칸 수, 목록 들여쓰기).
- 서비스별(ChatGPT, Gemini, Claude) 차이와 긴 출력이 잘리는 지점.

## 변경 내역

### v0.2 (2026-11-01) — 실험 01 4.2 반영
- 규칙 5: 출처 유형(수상·특허·발표 안건·과제 목록)을 명시하고, 횡단 블록에 나열한 과제도 빈 경험으로 만들게 함. ChatGPT가 발표 안건·대표 과제 목록의 과제(설계 최적화 과제, 운영 최적화 과제, 교류회)를 빈 경험으로 만들지 않음. Gemini는 전부 누락.
- 규칙 9: 기준 칸 접두어 반복("기준: 기준 없음") 금지, 조건·주기·기간을 정량 성과에 넣지 않도록. ChatGPT "현장 불량률 1%", "격주", "추진 기간 6개월".
- 출력 형식: 템플릿의 기준 칸을 "기준 없음"으로, "분해 끝" 종료 표시, 수치 중복 자가 확인. ChatGPT 중복 2건(GPU 플랫폼, 과제 배분).
- 규칙 11(v0.1.1): 역할 주체 구분. Claude·ChatGPT는 준수, Gemini는 "직접 구현"으로 격상.
